# Repository Structure Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan inline with a review checkpoint after each task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat `generator-*` module and package hierarchy with the approved layered modular-monolith structure while preserving CLI, Web, generated-project, validation, and archive behavior.

**Architecture:** Domain and application form the dependency-independent center. Configuration, OpenAPI, filesystem, validation, and version-specific emitters implement application ports; bootstrap composes them; CLI and Web remain delivery applications. Migration proceeds in buildable stages and removes the old hierarchy without compatibility shims.

**Tech Stack:** Java 21 generator runtime, generated Java 17/21 targets, Gradle 9.6.1, JUnit 5, Jackson 2/3 adapters, Swagger Parser, Spring Boot 3.5/4.1 generated stacks, Spring AI 1.1/2.0, MCP Streamable HTTP, Thymeleaf.

## Global Constraints

- Use the approved design in `docs/superpowers/specs/2026-08-12-repository-structure-refactor-design.md`.
- Keep `openapi-mcp`, CLI options, exit codes, stdout JSON, Web routes, Web payloads, and UI behavior compatible.
- Keep all four compatibility profile IDs, versions, generated paths, generated bytes, validation stages, and archive semantics compatible.
- Keep `domain` free of repository-module dependencies and `application` dependent only on `domain`.
- Do not introduce `common`, `core`, `util`, or `impl` packages.
- Do not add deprecated forwarding packages, old Gradle aliases, Spring-version branches in emitter support, or a placeholder MCP SDK emitter.
- Split a class only when responsibility, dependency, lifecycle, failure policy, or proven duplication provides a real boundary; never split by line count alone.
- Preserve fatal `Error` identity, interrupt flags, secret masking, telemetry completion, bounded process cleanup, and cross-platform path safety.
- Intermediate Gradle hierarchy projects are aggregation-only; Java conventions apply only to explicit leaf projects.
- Keep CI bounded to fast structural/core validation; run expensive four-profile boot/MCP acceptance locally before PR.
- Implement inline in this session. Do not dispatch subagents.
- Use meaningful `test:`, `refactor:`, or `docs:` commits; do not plan corrective `fix:` commits.
