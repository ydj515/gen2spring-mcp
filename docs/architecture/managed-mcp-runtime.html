→

2. Runtime request lifecycle

1. Authenticate

/mcp/{runtimeId} 경로와 bearer token을 매 요청 검증한다. miss, wrong, expired, revoked는 동일한 401이다.

2. Isolate handle

runtime ID와 Catalog checksum별 transport, server, session, Tool specifications를 한 번 생성한다.

3. Execute Tool

exact schema로 SDK가 입력을 검증하고 bounded executor가 request binding과 normalization을 수행한다.

4. Cross mTLS

runtime은 provider URL에 직접 연결하지 않고 bounded internal JSON을 provider-egress로 보낸다.

5. Resolve and connect

모든 DNS answer를 검사하고 connect-time resolver snapshot을 사용한다. redirect는 없다.

6. Close safely

만료·revoke·shutdown에서만 server와 session handle을 종료한다. 용량 초과는 활성 handle을 evict하지 않고 503으로 거부한다.
